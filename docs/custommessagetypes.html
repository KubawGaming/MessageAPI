Custom Message Types

Create your own message types by extending the base classes provided by MessageAPI.

Class Hierarchy

Message (abstract)
├── LocalizedMessage (abstract)
│   └── SoundableMessage (abstract)
│       ├── ChatMessage
│       ├── ChatListMessage
│       ├── ActionBarMessage
│       ├── AnimatedActionBarMessage
│       ├── TitleMessage
│       ├── AnimatedTitleMessage
│       ├── MultiMessage
│       └── EmptyMessage
└── (your custom messages)

Base Classes Overview

Message

The root abstract class. Provides:

  • messageDelay - Delay before sending (in ticks)
  • commands - List of console commands to execute (supports {PLAYER} placeholder)
  • sendTo*() - Built-in delivery methods (broadcast, permission filters, radius, predicates)
  • replace() - Placeholder replacement system
  • clone() - Immutable operations support
  • Utility methods: sendMessage(), sendActionBar(), sendTitle(), applyCommands()

LocalizedMessage

Extends Message. Adds support for location-based messages.

SoundableMessage

Extends LocalizedMessage. Adds sound effects support:

  • soundSettings - Paths, delay, volume, pitch
  • applySound() - Plays sound to recipient
  • inLocation() - Sets sound playback location

Creating a Custom Message

1. Minimal Implementation (No Sound, No Location)

package myplugin.messages;

import me.kubaw208.messageapi.structs.Message;
import org.bukkit.entity.Player;
import org.jetbrains.annotations.NotNull;

public class BossBarMessage extends Message {

    private String text;
    private float progress;

    public BossBarMessage(String text, float progress) {
        this.text = text;
        this.progress = progress;
    }

    @Override
    protected Message sendToInternal(@NotNull Player player) {
        applyCommands(player);
        // Your custom delivery logic here
        player.getBossBar(...); // Example
        return this;
    }

    @Override
    public Message replace(@NotNull String toReplace, @NotNull String replaced) {
        BossBarMessage cloned = this.clone();
        cloned.text = cloned.text.replace(toReplace, replaced);
        return cloned;
    }

    @Override
    public BossBarMessage clone() {
        return (BossBarMessage) super.clone();
    }
}

3. Full Example with JSON Support

package myplugin.messages;

import com.fasterxml.jackson.annotation.JsonCreator;
import com.fasterxml.jackson.annotation.JsonProperty;
import lombok.Getter;
import lombok.Setter;
import me.kubaw208.messageapi.structs.SoundableMessage;
import me.kubaw208.messageapi.utils.Utils;
import org.bukkit.entity.Player;
import org.jetbrains.annotations.NotNull;

@Getter
@Setter
public class BossBarMessage extends SoundableMessage {

    @JsonProperty("text")
    private String text;

    @JsonProperty("progress")
    private float progress;

    @JsonCreator
    public BossBarMessage(
        @JsonProperty("text") String text,
        @JsonProperty("progress") float progress
    ) {
        this.text = text;
        this.progress = progress;
    }

    @Override
    protected BossBarMessage sendToInternal(@NotNull Player player) {
        applySound(player);
        applyCommands(player);
        // Your custom logic
        return this;
    }

    @Override
    public BossBarMessage replace(@NotNull String toReplace, @NotNull String replaced) {
        BossBarMessage cloned = this.clone();
        cloned.text = cloned.text.replace(toReplace, replaced);
        return cloned;
    }

    @Override
    public BossBarMessage clone() {
        return (BossBarMessage) super.clone();
    }
}

JSON Serialization with Jackson

MessageAPI uses Jackson for YAML/JSON serialization and deserialization. The @JsonProperty annotations define which fields are serialized. @JsonCreator tells Jackson how to reconstruct your message from data.

Why Jackson? It allows MessageAPI to automatically save/load your custom message configurations to YAML files, and enables polymorphic deserialization (knowing which message type to create based on the data structure).

Registering Custom Type for JSON

Important: Register your custom message type after calling Message.init() to enable JSON deserialization. 
// During plugin startup
Message.init(this);
Message.registerMessageType(BossBarMessage.class);

// Your custom type is now ready for YAML/JSON
# config.yml
my-bossbar:
  text: "<red>Boss Health: {HEALTH}"
  progress: 0.75
  commands:
  - "say Boss damaged!"
  sound:
    paths:
    - "minecraft:entity.ender_dragon.growl"
    volume: 1.0
Note: If your message doesn't require sound or location, extend Message directly. Only extend SoundableMessage if you want sound effects.

Available Utility Methods

// From Message class (similar to BukkitAudience)
protected void sendMessage(CommandSender sender, Component message)      // Chat message with hex colors
protected void sendActionBar(Player player, Component message)           // Action bar with hex colors
protected void sendTitle(Player player, Component title, Component subtitle, int fadeIn, int stay, int fadeOut)  // Title with hex colors
protected void applyCommands(Player player)

// From SoundableMessage class
protected void applySound(Player player)

// Static utility
Utils.hexComponent("<red>Hello") // Converts MiniMessage to Component (supports hex colors `&#XXXXXX` for older versions)

These methods work like BukkitAudience, supporting hex colors (&#XXXXXX format) even on older Minecraft versions.
