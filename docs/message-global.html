Message (Global)

This section covers common features shared across all message types in MessageAPI. These properties and methods are available for every built-in message implementation.

Message Type

Every message in YAML configuration requires a messageType field for proper deserialization.

Available Message Types

  • CHAT - Standard chat message
  • CHAT_LIST - Multiple chat messages
  • ACTIONBAR - Action bar message
  • ANIMATED_ACTIONBAR - Animated action bar
  • TITLE - Title message
  • ANIMATED_TITLE - Animated title
  • MULTI - Multiple messages combined
  • EMPTY - Empty message (sound/commands only)

Message Delay

Delay message delivery by a specified number of ticks (20 ticks = 1 second).

Configuration (YAML)

welcome-message:
  messageType: CHAT
  message: "<green>Welcome to the server!"
  messageDelay: 40  # 2 seconds delay

Developer Usage

Use the sendTo() method variants with delay parameter:

Message message = new ChatMessage("<green>Welcome!");

// Send with 2 second delay (40 ticks), recommended usage
message.sendTo(player, 40);

// Or set delay and send
message.setMessageDelay(40).sendTo(player);

PlaceholderAPI support

You can use PlaceholderAPI placeholders in messages.

Configuration (YAML)

welcome-message:
  messageType: CHAT
  message: "<green>Welcome to the server %player_displayname%!"
  parsePlacehodlers: true  # default false

Developer Usage

Message message = new ChatMessage("<green>Welcome %player_displayname%!");

message.setParsePlaceholders(true).sendTo(player);

Commands

Execute commands when a message is sent. Commands are executed from the console with {PLAYER} placeholder support.

Configuration (YAML)

reward-message:
  messageType: CHAT
  message: "<gold>Reward claimed!"
  commands:
  - "give {PLAYER} diamond 1"
  - "effect give {PLAYER} speed 30 1"

Developer Usage

Message message = new ChatMessage("<gold>Reward claimed!");

message.setCommands(List.of(
    "give {PLAYER} diamond 1",
    "effect give {PLAYER} speed 30 1"
));
message.sendTo(player);

Sounds

Note: Sound support is available only for message types that extend SoundableMessage. All default message types in MessageAPI support sounds.

Attach sound effects to messages. When multiple sounds are defined, one is randomly selected for each player.

Configuration (YAML)

Basic Sound

level-up-message:
  messageType: CHAT
  message: "<green>Level Up!"
  sound:
    paths:
    - "minecraft:entity.player.levelup"

Multiple Sounds (Random Selection)

notification-message:
  messageType: ACTIONBAR
  message: "<yellow>Notification!"
  sound:
    paths:
    - "minecraft:block.note_block.pling"
    - "minecraft:block.note_block.chime"
    - "minecraft:block.note_block.bell"

Advanced Configuration

custom-message:
  messageType: TITLE
  title: "<gold>Custom Sound!"
  stay: 1000
  sound:
    paths:
    - "minecraft:entity.player.levelup"
    delay: 10      # Ticks before playing sound (default: 0)
    volume: 1.0    # Sound volume (default: 1.0)
    pitch: 1.0     # Sound pitch (default: 1.0)

Sound Properties

Property Type Default Description
paths List<String> [] Sound identifiers (one randomly selected per player)
delay Integer 0 Delay in ticks before playing sound
volume Float 1.0 Sound volume
pitch Float 1.0 Sound pitch

Developer Usage

Basic Sound

SoundableMessage message = new ChatMessage("<green>Level Up!");

message.setSoundPaths(List.of("minecraft:entity.player.levelup"))
        .sendTo(player);

Multiple Sounds with Configuration

SoundableMessage message = new ActionBarMessage("<yellow>Notification!");

message.setSoundPaths(List.of(
                "minecraft:block.note_block.pling",
                "minecraft:block.note_block.chime",
                "minecraft:block.note_block.bell"))
        .setSoundVolume(0.8f)
        .setSoundPitch(1.5f)
        .setSoundDelay(10)
        .sendTo(player);
Important: When multiple sound paths are provided, only one random sound is played per player. Sounds are not played simultaneously.
